# 统一 JSON 工作台设计

## 结论

当前“编辑器模式”和“分屏模式”应合并。两者处理的是同一份 JSON，只是结果展示不同，却分别维护输入框、工具栏、校验状态和窗口按钮。继续保留两个页面模式会放大状态同步、功能遗漏和 E2E 测试成本。

推荐改为单一工作台：左侧只有一个原始 JSON 编辑器，右侧结果区提供“树形视图”和“高亮预览”两个标签。桌面默认双栏，窄窗口使用编辑器/结果标签切换。

## 现状问题

- `#sourceText` 与 `#splitSourceText` 互相复制，任一事件遗漏都会产生内容分叉。
- `#valid-result` 与 `#split-valid-result` 分别维护，错误详情和实时状态可能不一致。
- 主工具栏和分屏工具栏重复提供格式化、清空、主题和窗口操作。
- `currentViewMode` 参与格式化、粘贴、刷新树和错误展示，增加不必要的条件分支。
- 高亮 JSON 与树形 JSON 都是解析结果，却分散在两个模式中，用户必须切换页面才能比较。
- 移动端的“分屏”概念不成立，应转换为同一数据源上的面板切换。

## 目标结构

```text
统一工具栏
├── 粘贴 / 格式化 / 清空
├── 转义 / 复制路径格式
├── 主题 / 窗口操作
└── 布局：仅编辑器 / 双栏 / 仅结果

工作区
├── JSON 编辑器（唯一 textarea）
└── 结果面板
    ├── 树形视图
    └── 高亮预览
```

唯一输入源建议沿用 `#sourceText`，移除 `#splitSourceText`。解析结果保存在内存状态中：

```ts
interface WorkbenchState {
  source: string;
  parsed: unknown | null;
  error: JsonParseError | null;
  resultView: 'tree' | 'highlight';
  layout: 'editor' | 'split' | 'result';
}
```

输入防抖后只执行一次解析。解析成功同时更新树和高亮结果；解析失败只更新统一状态条，并保留上一次结果或显示明确空状态。格式化按钮只负责将已解析对象写回编辑器，不再触发第二套流程。

## 交互规则

- 桌面首次启动使用双栏；保留用户上次布局。
- 右侧默认树形视图，可切换到高亮预览。
- 小于 `760px` 时一次只显示一个主面板，底部或顶部标签负责切换。
- Base64 图片、LaTeX、换行解释和路径复制在两个结果视图共享同一识别层。
- 格式化、粘贴、清空、主题和窗口控制只保留一组按钮。
- 旧的 `json_formatter_view_mode` 在首次启动时迁移到新 `layout`，随后删除旧键。

## 迁移顺序

1. 建立独立的解析状态和统一测试数据，不改变 UI。
2. 让两个现有输入框临时共享同一个状态入口，删除分散的解析分支。
3. 将树形视图和高亮预览移动到同一结果面板。
4. 删除重复输入框、工具栏和旧模式切换代码。
5. 更新 E2E 为单工作台契约，删除模式同步测试。

## 验收标准

- 页面中只存在一个可编辑 JSON 输入源。
- 相同输入只触发一次解析，树和高亮结果一致。
- 切换结果视图不会修改输入或重新解析。
- 桌面双栏和移动端单面板均可完成输入、校验、浏览和复制。
- E2E 不依赖测试执行顺序，不使用固定长等待，不引用实现中不存在的元素。
